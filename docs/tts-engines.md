# TTS 引擎选型

VoStory 统一使用 **Breeze-TTS-2** 作为语音合成引擎。本文档说明需求、选择理由与使用约束。

## 需求

- **固定的角色音色**：每个角色一个基础音色，整本书保持一致
- **按场景演绎**：同一角色在不同场景下语气、语速、情绪不同
- **没有现成配音素材也能开工**：上百个角色不可能都去找参考音频，需要能按文字描述生成音色
- **中文为主**：有声小说 / 广播剧
- **批量生成**：按章节离线合成，非实时对话

## 为什么是 Breeze-TTS-2

| 需求 | Breeze-TTS-2 能力 |
|------|------------------|
| 固定的角色音色 | Voice Clone：参考音频 + 逐字转写即可克隆 |
| 按场景演绎 | Voice Direction：保持参考音色，用自然语言指令调整语气、语速、情绪 |
| 按文字描述生成音色 | Voice Design：只给音色描述即可生成新音色 |
| 中文 | 中英双语单模型，支持 `[笑]`、`[叹气]`、`[咳嗽]`、`[清嗓子]` 等声音事件标签 |
| 部署 | 普通推理约 7.7GB 显存（建议 12GB+），`--fast-all` 约 14.4GB（建议 24GB） |

三种模式共用一个接口（`POST /v1/audio/speech`），由是否传参考音频和指令区分，正好对应 VoStory 的流程：

```
Voice Design  → 为角色生成基础音色（一次性，结果冻结为参考音频）
Voice Direction → 每个片段：基础音色 + 场景演绎指令
Voice Clone   → 无需特别演绎的片段：基础音色原样克隆
```

## 使用约束

- **许可**：源码 Apache 2.0；模型权重、衍生模型与自部署产出仅限研究与非商业用途。本项目仅供个人使用
- **参考文本必填**：克隆与导演模式都需要参考音频的逐字转写，转写不准会影响音色还原
- **无拼音标注**：多音字、专有名词通过发音词典替换为同音字解决
- **单并发**：官方流式 API 一次只处理一个请求，TTS 提供商并发数保持 1
- **单次时长**：`max_new_tokens` 上限 1500（12.5 token/秒，约 120 秒音频），脚本片段远低于此限制
- **随机性**：同一参考音频在不同种子下会有细微差异，VoStory 对每个声音配置固定种子
